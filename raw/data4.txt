This book teaches you to build a small but fully working Large Language Model (LLM)

possible next piece of text is. Give it "The cat sat on the" and it scores every token it

It is not a database or a search engine. It does not look facts up. Whatever it "knows"
is compressed into its parameters as statistical patterns.
It is not a rule engine. Nobody programmed grammar or logic into it. These abilities
appear because predicting text well requires them.
It optimizes for plausible, not for true. A fluent but false sentence can score highly.
This is called hallucination, and it is why you must test model output.
It only knows its training data. The model you build will write like your data and know
what your data contains, nothing more. This is the single most important fact for
planning a custom model.
"Large" is relative. Frontier models have hundreds of billions of parameters; the
models in this book have 1 to 90 million. Same idea, much smaller scale.
0.3 Machine learning in one page
Traditional programming means you write the rules. Machine learning means you show
examples and let the computer find the rules. Every ML system has three ingredients:
1. A model: a function with adjustable numbers (parameters).
2. A loss: a score for how wrong the model currently is.
3. An optimizer: a procedure that adjusts the parameters to lower the loss.
The basic building block is the neuron: multiply each input by a weight, add them up, add a
bias, and pass the result through a non-linear activation function (such as GELU).
output = activation( w1*x1 + w2*x2 + ... + bias )
A layer is many neurons side by side; a neural network is layers stacked. The activation
function matters: without it, stacking many layers would collapse into one simple linear
function and could not learn language. A network is therefore a very large formula with
millions of knobs, and training is the search for good knob settings.
0.4The only math you need
Three ideas cover almost everything in this book.
Vector: a list of numbers, such as the 384 numbers that represent one token.
Dot product: multiply two vectors element by element and add the results. A large
value means the vectors point the same way (they are "similar"). Attention is built on
this.

Matrix multiplication: applying a whole grid of weights to a vector (or to many vectors
at once). Every layer of the model is a matrix multiplication.
import torch
a = torch.tensor([1.0, 2.0, 3.0]) # a vector, shape (3,)
M = torch.tensor([[1., 0.], [0., 1.], [1., 1.]]) # a matrix, shape (3,
2)
print(torch.dot(a, a)) # 1*1 + 2*2 + 3*3 = tensor(14.)
print(a @ M) # shape (3,) times (3, 2) gives shape (2,):
tensor([4., 5.])
The shape rule: when you multiply (n, k) @ (k, m) , the two inner numbers must match
and the result is (n, m) . When code crashes, nine times out of ten the shapes disagree.
Make it a habit to print(x.shape) while you build.
0.5 Probability and softmax
The model's final output for each position is a list of raw scores, one per token, called
logits. Logits can be any number, positive or negative. Softmax converts them into a
probability distribution: every value between 0 and 1, all adding up to exactly 1.
import torch
scores = torch.tensor([2.0, 1.0, 0.1])
probs = torch.softmax(scores, dim=0)
print(probs) # about [0.66, 0.24, 0.10]
print(probs.sum()) # 1.0
The biggest score gets the biggest share, but not all of it. To generate text we then sample
from these probabilities, so the likeliest token is chosen most often but not always. That
randomness is why the same prompt can produce different text, and it is what the
temperature setting in Chapter 9 controls.
0.6 Loss and cross-entropy
To train, we need one number that says how bad the predictions are. For next-token
prediction we use cross-entropy: look at the probability p the model gave to the token
that actually came next, and take the negative natural logarithm.

0.7 How learning works: gradient descent and backpropagation
Imagine the loss as the height of a landscape, where every parameter is a direction you
can walk in. You are standing somewhere on a foggy hillside and want to reach the valley.
The gradient tells you which way is steepest uphill for every parameter at once; you step
the opposite way. The size of each step is the learning rate: too small and you crawl, too
large and you overshoot and bounce around.
Backpropagation is the efficient algorithm that computes the gradient for all millions of
parameters in one backward sweep through the network. You never write it yourself:
PyTorch's autograd records every operation during the forward pass and replays it
backwards when you call loss.backward() .
Here is the whole idea at toy scale: a model with just two parameters learns the rule y =
2x + 1 from examples.

0.9 Language as numbers:tokens, embeddings, context
A computer cannot read letters, so text goes through three conversions that you will build
in Chapters 4 and 6:
1. Tokens: text is cut into pieces (words, word parts or characters) and each piece gets
an integer ID from a fixed list called the vocabulary.
2. Embeddings: each ID is swapped for a learned vector of numbers. During training,
tokens used in similar ways end up with similar vectors, so meaning becomes
geometry.
3. Context window: the model can only read a fixed number of tokens at once
( block_size ). Anything older is invisible to it. This is its entire working memory.
Word order matters, so the model also adds a position signal. Then attention lets each
token look back at earlier ones and pull in what is relevant, for example connecting "it" to
the noun it refers to. That mechanism is the heart of the transformer, and Chapter 6 builds
it step by step.

0.10 Pretraining,fine-tuning and inference
A model straight after pretraining is a base model: it continues text but does not follow
instructions. A chat or instruct model is a base model that was fine-tuned on question
and answer examples. You train once and then use the model many times, so training cost
is paid up front.
0.11 Practicalfoundations: overfitting, splits and hardware
Generalization and overfitting. The goal is a model that works on text it has never seen. A
model that memorizes its training text scores well there and badly on new text. That is
why we always hold back validation data that the model never trains on (Chapter 5) and
compare the two losses (Chapter 8). The smaller your dataset, the sooner overfitting
appears.
Memory. Each parameter is a number that must be stored. Training with the AdamW
optimizer in 32-bit precision needs about 16 bytes per parameter: 4 for the weight, 4 for
its gradient, and 8 for the optimizer's two running averages. Activations add more on top.
Running a trained model needs only 2 to 4 bytes per parameter.

0.12Building responsibly
Data rights: use text you own or are licensed to use. Public does not always mean free
to train on.
Privacy: models memorize. Remove personal details, passwords and keys before
training, and never train on other people's private messages.
Bias: a model repeats the patterns, including the unfair ones, in its data. Read samples
of your data before you train.
Trust: never present model output as verified fact. State clearly when text was
machine-generated.
Honest limits: a small model trained on little data is a learning tool and a style imitator,
not an authority.

1.TheBig Picture:What an LLM Really Is
The one idea behind everything
An LLM does exactly one job: given some text, predict the next piece of text. That is all.
If you type "The capital of France is", the model assigns a high probability to " Paris". To
write a whole paragraph, it predicts one token, adds it to the text, and predicts again.
Chatting, summarizing, coding and translating are all this same trick, repeated.
Training is how the model learns these probabilities. We show it huge amounts of text, ask
"what comes next?" at every position, compare its guess with the real answer, and nudge
its internal numbers (the parameters or weights) so the next guess is slightly better.
Repeat millions of times.

How Byte PairEncoding (BPE) works
BPE starts with single bytes and repeatedly merges the most frequent adjacent pair into
a new token.
Take the string aaabdaaabac :
1. Most frequent pair is aa . Replace it with a new symbol Z . Text becomes ZabdZabac .
2. Most frequent pair is now ab . Replace it with Y . Text becomes ZYdZYac .
3. Most frequent pair is ZY . Replace it with X . Text becomes XdXac .
The list of merges (in order) is the tokenizer. To encode new text, replay the same merges
in the same order. Because we start from raw bytes, any text in any language can be
encoded, so there are never "unknown" tokens.
Quick-start alternative: character-level
For a first experiment on a tiny file, a character tokenizer is just five lines:
text = open("data/input.txt", encoding="utf-8").read()
chars = sorted(set(text))
stoi = {c: i for i, c in enumerate(chars)} # char -> id
itos = {i: c for c, i in stoi.items()} # id -> char
encode = lambda s: [stoi[c] for c in s]
decode = lambda ids: "".join(itos[i] for i in ids)
The rest of this book uses BPE, because it makes the model see more text per training
step.

PAT = re.compile(r"\s?\w+|\s?[^\w\s]+|\s+")
class BPETokenizer:
def __init__(self):
self.merges = {} # (id_a, id_b) ->
new id
self.vocab = {i: bytes([i]) for i in range(256)} # id -> bytes
self.cache = {}
@staticmethod
def _merge(ids, pair, new_id):
out, i = [], 0
while i < len(ids):
if i < len(ids) - 1 and ids[i] == pair[0] and ids[i + 1] ==
pair[1]:
out.append(new_id)
i += 2
else:
out.append(ids[i])
i += 1
return out
def train(self, text, vocab_size):
words = Counter(PAT.findall(text)) # piece ->
count
seqs = {w: list(w.encode("utf-8")) for w in words} # piece ->
byte ids
for new_id in range(256, vocab_size):
stats = Counter()
for w, count in words.items():
s = seqs[w]
for pair in zip(s, s[1:]):
stats[pair] += count
if not stats:
break
best = max(stats, key=stats.get) # most
frequent pair
for w in seqs:
seqs[w] = self._merge(seqs[w], best, new_id)
self.merges[best] = new_id
self.vocab[new_id] = self.vocab[best[0]] + self.vocab[best[1]]
if new_id % 200 == 0:
print(f"merge {new_id - 255}/{vocab_size - 256}")

while len(ids) >= 2:
pairs = set(zip(ids, ids[1:]))
pair = min(pairs, key=lambda p: self.merges.get(p, float("inf")))
if pair not in self.merges:
break
ids = self._merge(ids, pair, self.merges[pair])
self.cache[piece] = ids
return ids
def encode(self, text):
out = []
for piece in PAT.findall(text):
out.extend(self._encode_piece(piece))
return out
def decode(self, ids):
return b"".join(self.vocab[i] for i in ids).decode("utf-8",
errors="replace")

6.1 Notation:the shape ofthe data

6.2Embeddings: giving tokens meaning
A token ID such as 1042 is just a label. The model needs a rich vector of numbers it can
compute with. An embedding table is a matrix with one row per token ( vocab_size rows,
n_embd columns). Looking up token 1042 means reading row 1042. Those rows start
random and are learned during training, so tokens used in similar ways end up with similar
vectors.
Attention has no built-in sense of word order, so we also learn a position embedding: one
vector per position (0, 1, 2, up to block_size - 1 ). The input to the transformer is simply
the two added together:
x = token_embedding[token_id] + position_embedding[position]
6.3 Self-attention:tokens looking at each other
To predict the next word in "The cat sat on the ___", the model must connect "the" with
"cat" and "sat". Self-attention is the mechanism that lets every token look at the earlier
tokens and collect useful information from them.
Each token creates three vectors by multiplying its embedding with three learned
matrices:
Query (Q): "what am I looking for?"

Key (K): "what do I contain?"
Value (V): "what information will I hand over if you pick me?"
The steps:
1. Compare the Query of the current token with the Key of every earlier token (a dot
product). A high score means "relevant".
2. Divide by the square root of the head size. This keeps scores small so the next step
stays stable.
3. Apply softmax, which turns the scores into weights that are positive and add up to 1.
4. Output the weighted average of the Values.
As one formula:
\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\left(\frac{QK^{\top}}
{\sqrt{d_k}}\right)V
The causal mask. When training, the model sees the whole sentence at once, but it must
not peek at future tokens or it could simply copy the answer. We hide the future by
setting the scores of all later positions to minus infinity before the softmax, so their
weights become exactly 0. This is called causal (or masked) attention, and it is what
makes the model a text generator.

column t .

6.4 Multi-head attention: several views at once
One attention pattern is not enough. One head may track grammar, another may track
names, another may look at the previous token. Multi-head attention splits the C
channels into n_head groups and runs attention in each group in parallel. With C = 384
and n_head = 6 , each head works with 64 channels. The head outputs are concatenated
back to size C and mixed by one more linear layer (the projection).
6.5 Feed-forward network (MLP):thinking per token
Attention moves information between tokens. The feed-forward network then processes
each token on its own: expand the vector 4 times wider, apply a non-linearity (GELU), and
shrink back. This is where much of the model's stored knowledge lives, and it holds about
two thirds of the parameters.
6.6 Residual connections and LayerNorm: keeping deep networks trainable
Residual connection: each sub-layer adds its result to its own input, x = x +
sublayer(x) . The original signal always has a clear path through the network, which
makes gradients flow and deep stacks trainable.
LayerNorm: rescales each token vector to a stable mean and spread. We apply it
before each sub-layer (called "pre-norm"), the layout GPT-2 and most modern models
use.
Dropout: randomly zeroes a few values during training so the model cannot rely on any
single path. Essential for small datasets.
Checkpoint: run the 10-line attention example. The printed 4 by 4 matrix must be lowertriangular (zeros above the diagonal) with each row adding up to 1.

class CausalSelfAttention(nn.Module):
def __init__(self, cfg):
super().__init__()
assert cfg.n_embd % cfg.n_head == 0
self.n_head = cfg.n_head
self.dropout = cfg.dropout
self.qkv = nn.Linear(cfg.n_embd, 3 * cfg.n_embd, bias=False) # Q,
K, V in one matrix
self.proj = nn.Linear(cfg.n_embd, cfg.n_embd, bias=False)
self.resid_drop = nn.Dropout(cfg.dropout)
def forward(self, x):
B, T, C = x.shape
q, k, v = self.qkv(x).split(C, dim=2)
# (B, T, C) -> (B, n_head, T, head_size)
q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
# fused, fast version of: softmax(q k^T / sqrt(d)) with causal mask,
times v
y = F.scaled_dot_product_attention(
q, k, v, is_causal=True,
dropout_p=self.dropout if self.training else 0.0)
y = y.transpose(1, 2).contiguous().view(B, T, C) # rejoin the heads
return self.resid_drop(self.proj(y))

class MLP(nn.Module):

def __init__(self, cfg):
super().__init__()

self.ln2 = nn.LayerNorm(cfg.n_embd)
self.mlp = MLP(cfg)
def forward(self, x):

x = x + self.mlp(self.ln2(x)) # residual around MLP

def generate(self, idx, max_new_tokens, temperature=0.8, top_k=50):

context window
logits, _ = self(idx_cond)
logits = logits[:, -1, :] / max(temperature, 1e-5) # only the
last position matters
if top_k:
v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
logits[logits < v[:, [-1]]] = float("-inf")
probs = F.softmax(logits, dim=-1)
next_id = torch.multinomial(probs, num_samples=1)
idx = torch.cat([idx, next_id], dim=1)
return idx

2. Forward pass: the model predicts a probability for every possible next token at every
position.
3. Loss: cross-entropy measures how much probability the model gave to the correct
next token. Giving it 90% costs little; giving it 0.1% costs a lot.
4. Backward pass: autograd computes, for every parameter, how a tiny change would
change the loss (the gradient).
5. Update: the optimizer (AdamW) moves every parameter a small step in the direction
that lowers the loss. The step size is the learning rate.
The loss (highlighted) is the number you watch while training; the other four steps exist to
make it smaller.

10.4 LoRA:fine-tuning with a tiny number of new parameters
Full fine-tuning updates every weight. LoRA (Low-Rank Adaptation) freezes the original
weight matrix W and learns a small correction as the product of two thin matrices, B and
A :
W' = W + \frac{\alpha}{r} \, B A \qquad B \in \mathbb{R}^{d_{out} \times
r},\; A \in \mathbb{R}^{r \times d_{in}}
For a 384 by 384 layer, the full matrix has 147,456 values; a rank r = 8 correction has only
6,144 (about 4%). Benefits: far less memory, fast training, and you can keep many small
adapters (one per task) for the same base model. The same trick scales to billionparameter models.
The input flows through the frozen original weights and, in parallel, through the small
trainable pair. Their outputs are added, so training changes behavior without touching W .

class LoRALinear(nn.Module):

super().__init__()

for p in self.base.parameters():
p.requires_grad = False #
freeze original weights
self.A = nn.Parameter(torch.randn(r, base.in_features) * 0.01)
self.B = nn.Parameter(torch.zeros(base.out_features, r)) # zeros:
starts as the original model
self.scale = alpha / r
def forward(self, x):
return self.base(x) + (x @ self.A.T @ self.B.T) * self.scale

10.6Tips for good fine-tuning
Watch for overfitting: if the model repeats training answers word for word on new
questions, lower steps or add more varied examples.
Be consistent: the same style, the same format, no contradicting answers.
Include variety: ask the same thing in several different ways.
Test on questions you did not train on, and keep a small list of test prompts to
compare before and after.
Do not train on private data you would not want repeated, because the model can
reproduce it.

12. Scaling Up and Modern Upgrades
12.1What really improves a model
Research on scaling laws gives a simple order of priorities for a fixed budget:
1. More and better data (the biggest lever for small models).
2. More training steps until validation loss stops improving.
3. A bigger model, but only if you have the data to feed it (about 20 tokens per
parameter).
4. Architecture tweaks, which give smaller but real gains.

def __init__(self, dim, eps=1e-6):
super().__init__()

Appendix D: Frequently Asked Questions
Can I train on a language other than English? Yes. The tokenizer works on raw bytes, so
any script is supported. Two adjustments help: use a larger VOCAB_SIZE in prepare.py
(4,000 to 8,000), because many scripts use several bytes per character; and for scripts
that combine letters with vowel signs (such as Hindi or Bengali), change the splitting
pattern at the top of bpe.py to PAT = re.compile(r"\s?\S+|\s+") , which splits on
whitespace only. You still need enough text in that language.
